# hw-ai-agent

Консольный coding agent на Python: получает задачу, изучает файлы, предлагает
план, изменяет код и запускает проверку. Цикл работы и управление инструментами
реализованы в проекте без агентного фреймворка. Подключение модели — через
OpenAI-совместимый Chat Completions API.

Поддерживаются OpenRouter, прямой OpenAI и локальная Ollama. Нужны Python 3.11+
и `certifi`. Для Bash требуется macOS с `/usr/bin/sandbox-exec`; на других ОС
исполнение команд отклоняется. Небезопасного запасного режима нет.

## Что реализовано

- Чтение и список файлов, запись, восстановимое удаление и ограниченный Bash.
- Режимы Safe/Auto, JSON-policy, защита тестов, секретов и границ рабочей папки.
- Сохранение сессий в SQLite, пауза, продолжение и явное разрешение неоднозначных вызовов.
- Планирование с утверждением плана в терминале до изменения файлов.
- Общие бюджеты запросов к модели, инструментов, действий и объёма результатов.
- Задачи с зависимостями, чек-листом и проверкой фактического результата.
- Журнал изменений, просмотр diff и откат с обнаружением внешних правок.
- Предварительная оценка стоимости, учёт расхода сессии, сравнение тарифов моделей.
- Выбор модели в терминале и автоматический выбор по сложности задачи при старте.
- Настройки через `.env` и CLI, русская справка, демонстрации и автоматические тесты.

## Установка

```bash
git clone https://github.com/SmegCoder/hw_ai_agent.git
cd hw_ai_agent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
hw-ai-agent help
```

`python3` должен быть версии 3.11 или новее. В PyCharm выберите интерпретатор
`.venv/bin/python`. Все команды ниже запускаются из корня проекта с активированной
`.venv`. Можно также использовать `python -m hw_ai_agent` вместо `hw-ai-agent`.

## Подключение модели

Для нового файла настроек:

```bash
hw-ai-agent setup --provider openrouter --model deepseek/deepseek-v3.2
hw-ai-agent doctor --provider openrouter
hw-ai-agent demo --provider openrouter --mode safe
```

`setup` запрашивает ключ скрытым вводом и создаёт `.env` с правами `0600`.
Существующий файл не перезаписывается. Если `.env` уже настроен, пропустите
`setup`; параметры меняйте через `set`, ключи — локально в файле.
`doctor` проверяет настройки и доступность сервиса. `demo` обращается к настоящей модели.

Для другого провайдера можно создать отдельный профиль:

```bash
hw-ai-agent setup --env-file .env.openai --provider openai --model gpt-4.1-mini
hw-ai-agent demo --env-file .env.openai --provider openai --mode safe

hw-ai-agent setup --env-file .env.ollama --provider ollama --model qwen3:4b
hw-ai-agent demo --env-file .env.ollama --provider ollama --mode auto
```

Для Ollama заранее запустите локальный сервер и загрузите модель с поддержкой
tools. ID должен совпадать с установленным тегом. OpenRouter/OpenAI требуют
собственного ключа и доступной модели; их генерация может тарифицироваться.
Профиль `.env.ollama` не требует ключа. Пример переменных — [.env.example](.env.example).

## Работа со своей папкой

Рабочая папка должна существовать. Модель получает доступ к ней через инструменты;
ключи, policy и база сессий должны находиться вне этой папки.

```bash
hw-ai-agent run --workspace /path/to/my-project \
  "Исправь расчёт суммы заказа и проверь существующими unittest-тестами"

hw-ai-agent plan --workspace /path/to/my-project --mode safe \
  --tasks --journal --max-rounds 30 --max-tokens 4096 \
  "Исправь расчёт суммы заказа и проверь существующими unittest-тестами"
```

`plan` автоматически добавляет инструкцию составить структурированный план;
писать «сначала составь план» в задаче не нужно. До утверждения разрешены только
список и чтение файлов, Bash и изменения запрещены. В терминале `y` утверждает
план, `n` отклоняет и завершает сессию, Enter оставляет её на паузе.
`run --plan` включает то же поведение. `--tasks` автоматически включает планирование.

План содержит цель, шаги, нужные инструменты, риски, предположения и критерии
завершения. При режиме задач шаги дополнительно получают ID, зависимости и
проверку результата. План и решение пользователя сохраняются в SQLite.

## Режимы и policy

| Действие | `safe` | `auto` |
| --- | --- | --- |
| Список и чтение файлов | По policy | По policy |
| Запись | Подтверждение каждого вызова | Сразу после проверок |
| Bash | Подтверждение каждого вызова | Сразу после проверок |
| Удаление | Подтверждение каждого вызова | Подтверждение каждого вызова |

По умолчанию чтение разрешено. Policy может дополнительно запретить его или
потребовать подтверждение. В Safe `allow` не отменяет подтверждение записи/Bash.
В Auto для записи/Bash отдельного разрешения на сессию нет. Явный `deny` действует
в обоих режимах и не может быть отменён ответом пользователя.

Перед записью показывается diff, перед удалением — цель и размер.
`--approvals ask` задаёт вопросы; `--approvals deny` отклоняет действия, требующие
этого подтверждения. Это не автоматическое согласие. Утверждение плана и решения
конфликтов задаются отдельно. Если нужен ответ, а stdin не является терминалом,
ожидание сохраняется и запуск останавливается с кодом 130; продолжите через `resume`.

```bash
hw-ai-agent run --workspace /path/to/my-project --mode safe \
  --policy policies/readonly.json "Объясни устройство проекта"
hw-ai-agent demo --mode auto --policy policies/demo.json --approvals deny
```

Готовые профили:

| Файл | Назначение |
| --- | --- |
| [readonly.json](policies/readonly.json) | Только список и чтение; изменения и Bash запрещены |
| [review.json](policies/review.json) | Просмотр и правки с ограниченным набором команд; каталог `private` закрыт |
| [demo.json](policies/demo.json) | Запись только `order.py`, конкретная команда тестов, удаление запрещено |

JSON-policy задаёт `defaults`, `rules` и `directories.allow/deny`. Приоритет решений
— `deny`, затем `ask`, затем `allow`. Загруженный файл является полной конфигурацией:
неуказанные инструменты запрещены, без `directories.allow` доступных каталогов нет.
Подробнее — [Policy и подтверждения](docs/POLICY_RESULTS.md).

### Границы инструментов

Все вызовы проходят проверку аргументов, путей, policy и режима. Запрещены выход
за workspace, работа через симлинки и жёсткие ссылки, изменение тестов и доступ
к защищённым секретам. Файловые операции повторно проверяют цель после
подтверждения; подмена файла или каталога приводит к отказу.

Bash допускает ограниченные команды: `python -m unittest`, `pwd`, `ls`, `cat`,
`sleep`. Pipes, перенаправления, произвольные скрипты, `python -c`, `pytest`
и `npm` не поддерживаются. Дочернему процессу запрещены сеть и запись в workspace,
а вывод и время исполнения ограничены. Тесты с записью временных файлов могут
не работать в такой песочнице.

`delete_file` удаляет только обычный файл и сохраняет восстановимую копию в
`trash/RECOVERY_ID/file` рядом с базой сессий. `info.json` содержит исходный путь.
Это не автоматический откат; каталоги не удаляются, перенос между файловыми
системами отклоняется. Подробнее — [Руководство по workflow](docs/WORKFLOW_GUIDE.md).

## Сессии, пауза и продолжение

```bash
hw-ai-agent plan --workspace /path/to/my-project --stop-after-tools 2 "Исправь ошибку"
hw-ai-agent sessions
hw-ai-agent resume
hw-ai-agent session SESSION_ID
hw-ai-agent resume SESSION_ID
```

Без ID `resume` в интерактивном терминале выбирает единственную незавершённую
сессию или показывает меню. Для автоматизации без терминала передайте ID.
Флаги паузы не наследуются. Для отдельного профиля и базы при продолжении укажите
те же `--env-file` и `--state-db`.

SQLite хранит историю, вызовы и результаты, план, задачи, бюджеты и стоимость.
Путь по умолчанию — `.agent/sessions.sqlite3`, вне workspace. API-ключ из настроек
не записывается в метаданные; рабочая история не зашифрована.
Повтор завершённого ID вызова возвращает сохранённый результат; изменение его
имени или аргументов является ошибкой протокола.

Модель, провайдер, адрес сервиса, режим, policy и лимиты фиксируются в сессии.
`resume` не поддерживает их переопределение; изменённая policy или несовместимое
подключение блокируют продолжение. Изменение `.env` или `set` влияет на новые
запуски. При `resume` можно менять вывод оценки стоимости, способ подтверждений
и флаги паузы. Одновременное продолжение одной сессии блокируется.

### Неопределённый результат после сбоя

Если действие началось, но его результат не сохранён, оно становится `uncertain`.
Даже чтение не повторяется молча. `resume` показывает состояние и меню:

| Выбор | Действие |
| --- | --- |
| `1` / `retry` | Повторить поддержанный инструмент после проверок; новая попытка расходует бюджет |
| `2` / `skip` | Сохранить ошибку вызова и продолжить |
| `3` / `abort` | Завершить сессию с ошибкой |
| `4` / `applied` | Признать запись только при точном совпадении байтов с запрошенным содержимым |
| `0` | Оставить сессию заблокированной |

`skip` и `abort` не отменяют уже случившиеся изменения. При включённом журнале
дополнительно требуется указать принадлежность обнаруженных изменений:
`own` — изменения сессии, `external` — внешние. Подробнее и команды для
автоматизации — [Сохранение сессий](docs/SESSION_RESULTS.md).

## Бюджеты

| Флаг | Что ограничивает | Встроенное значение для `run` |
| --- | --- | ---: |
| `--max-rounds` | Все попытки запросов к модели | 12 |
| `--max-tool-calls` | Вызовы инструментов | 128 |
| `--max-side-effects` | Попытки записи, удаления и Bash | 32 |
| `--max-result-bytes` | Суммарные байты UTF-8 результатов инструментов | 1 000 000 |
| `--max-tokens` | Выходные токены одного ответа модели | 2048 |

Первые четыре бюджета общие для планирования, исполнения и `resume`.
Пачка инструментов резервируется целиком до первого действия: при недостатке
бюджета её начало не выполняется. Большие результаты обрезаются с отметкой.
После аварии неиспользованный резерв неопределённого вызова не возвращается.
Повтор, ручное решение и откат не обнуляют бюджет. При исчерпании сохраняется
`budget_exhausted`; увеличить лимиты через `resume` нельзя.

`--max-rounds` и `--max-tokens` должны быть не меньше 1; три остальных бюджета
могут быть нулевыми. Bash учитывается как потенциальный побочный эффект, хотя
песочница запрещает ему запись. `--max-tokens` не задаёт контекст, общий объём
токенов или денежный лимит. Отдельные исходные и итоговые проверки демо выполняются
проверяющим кодом вне бюджета агента.

## Задачи с зависимостями

`--tasks` превращает утверждённый план в задачи с `id`, `depends_on`, инструментами
и `verification`. Валидатор проверяет ссылки и отсутствие циклов. Планировщик
запускает готовые задачи по очереди; каждый исполнительный вызов связан с задачей.
Чек-лист показывает ожидание, исполнение, успех, ошибку и блокировку зависимостей.

Модель вызывает `complete_task`, но результат проверяет runtime:

- `file_written` — текущие байты совпадают с последней успешной записью этой задачи;
- `file_read` — файл соответствует полному чтению этой задачи;
- `file_absent` — удалённый файл отсутствует;
- `tests_passed` — нужная команда unittest прошла, запускала тесты и её вывод не обрезан.

Текст «готово» и доказательства, придуманные моделью, не завершают задачу.
Ошибка блокирует зависимые задачи; независимые могут продолжиться. После `resume`
завершённые задачи не исполняются заново. Состояния и проверенное доказательство
сохраняются в SQLite вместе с завершением задачи.

## Журнал изменений и откат

Журнал включается **при создании** сессии через `--journal`.
Для старого запуска без журнала откат недоступен.

```bash
hw-ai-agent plan --workspace /path/to/my-project --journal "Исправь ошибку"
hw-ai-agent changes
hw-ai-agent rollback
```

`changes [SESSION_ID]` показывает diff, `rollback [SESSION_ID]` возвращает исходные
байты и обычные права доступа изменённых файлов; созданные агентом файлы удаляются.
Откат запускается отдельной командой, доступен и для завершённой сессии.
Каждое удаление при откате подтверждается в обоих режимах.

Перед изменяющим инструментом фактическое дерево сверяется с последней контрольной
точкой. Внешняя правка блокирует действие. Перед откатом проверяются все затронутые
файлы, сохранённые данные и текущая policy. Конфликт или отказ при предварительных
подтверждениях не запускает восстановление. Чужие изменения незатронутых файлов
сохраняются. Проверки повторяются после подтверждений.

Многофайловый откат не является атомарной транзакцией файловой системы:
авария или гонка во время исполнения может оставить часть восстановленной.
Состояние `rollback_pending` сохраняется; повторный `rollback` явно продолжает
оставшиеся операции. После успешного отката сессия получает `rolled_back`
и исполнение агента не возобновляется. История, стоимость и бюджет сохраняются.

Ограничения снимка: 2000 путей, 10 MiB на файл, 20 MiB на дерево.
Защищённые служебные файлы и собственный JSON-отчёт демо исключаются;
обычные JSON-файлы отслеживаются. Снимок не обходит запрет чтения policy.
Восстанавливаются байты и mode, но не владелец, ACL или xattr; пустые каталоги
могут остаться. Подробнее — [Руководство по workflow](docs/WORKFLOW_GUIDE.md).

## Стоимость и выбор модели

По умолчанию перед каждым запросом показывается приблизительная цена при выходе
от 0 до `--max-tokens`. Оценка учитывает историю и схемы инструментов, использует
приближение числа токенов и не предсказывает стоимость всей будущей задачи.
После ответа и по завершении показывается накопленный расход сессии.

```bash
hw-ai-agent run --workspace /path/to/my-project --no-cost-estimate "Исправь ошибку"
hw-ai-agent resume --cost-estimate
hw-ai-agent cost
hw-ai-agent cost SESSION_ID
hw-ai-agent set --no-cost-estimate
```

`AGENT_COST_ESTIMATE=true/false` задаёт значение по умолчанию.
`--no-cost-estimate` отключает предварительную оценку, но учёт фактического
расхода продолжает работать. Этот флаг доступен также при `resume`.

Для OpenRouter приоритет имеет сообщённый `usage.cost`. Для OpenAI сумма
рассчитывается по фактическим токенам и тарифам Standard, с учётом известных
тарифов кэша и длинного контекста. Это расчёт, а не сверка счёта аккаунта.
Ollama и подставные клиенты имеют нулевую плату API; расходы компьютера не учтены.
Неизвестная цена или запрос без сохранённых данных не считаются бесплатными.
Подтверждённые и расчётные суммы хранятся отдельно, суммирование использует Decimal.
Отклонённый ответ модели тоже может быть платным; `resume` и откат не обнуляют расход.

### Сравнение тарифов

```bash
hw-ai-agent models --provider openrouter --refresh
hw-ai-agent models --provider openrouter --paid --limit 100
hw-ai-agent models --provider openrouter --free --sort price
hw-ai-agent models --provider openrouter --search deepseek --all
hw-ai-agent models --provider openai --search gpt-4.1
hw-ai-agent models --provider ollama
hw-ai-agent models --provider openrouter --input-tokens 10000 --output-tokens 2000 --json
```

Колонки показывают полный ID, тариф входа/выхода за миллион токенов, контекст,
поддержку tools и цену одинакового сценария. По умолчанию — до 50 моделей по
имени, сначала с подтверждёнными tools; `--all` снимает лимит, `--limit` допускает
1–5000. `--paid` и `--free` взаимоисключающие, неизвестные цены исключаются из них.
Это сравнение тарифов, а не рейтинг популярности или качества.

OpenRouter использует публичный каталог, OpenAI — официальную таблицу Standard,
Ollama — установленные модели и их capabilities. Кэш вне workspace действует
час; при сбое старые данные помечаются устаревшими с датой. Без данных цена
неизвестна. Для нестандартного endpoint или неподтверждённого service tier
официальный тариф не подставляется. Каталог не гарантирует доступ модели аккаунту.

### Ручной и автоматический выбор

```bash
hw-ai-agent run --workspace /path/to/my-project --model '?' "Исправь ошибку"
hw-ai-agent plan --workspace /path/to/my-project --model auto "Исправь ошибку"
hw-ai-agent set --route
hw-ai-agent set --no-route
```

`--model '?'` показывает до 20 вариантов с ценами и номерами; кавычки защищают
`?` от обработки оболочкой. Enter/0/EOF отменяют выбор. Для запуска без терминала
нужен явный ID или `auto`. Выбор не меняет `.env`.

`--model auto` или `--route` локально оценивают описание задачи, планирование и
режим задач, затем выбирают одну модель из набора simple/medium/complex.
Платного классификатора нет. Причины выбора печатаются и сохраняются; при
`resume` модель не выбирается заново. Явный `--model ID` имеет приоритет над
`AGENT_ROUTE`. Наборы определены в [routing.py](src/hw_ai_agent/routing.py).

Переопределения: `--route-simple-model`, `--route-medium-model`,
`--route-complex-model`. Модель должна иметь подтверждённые tools, известный
тариф и подходящие известные лимиты. При отсутствии кандидата запуск завершается
ошибкой. Эвристика не гарантирует лучшего качества; жёсткого денежного бюджета нет.

## Настройки и флаги

Приоритет: **CLI → экспортированная переменная → `.env` → встроенное значение**.
`set` сохраняет только указанные настройки, сохраняет остальные строки и ключи,
создаёт файл при необходимости, не вызывает модель. Уже экспортированная
переменная продолжает иметь приоритет над записанным файлом.

```bash
hw-ai-agent set --provider ollama --model qwen3:4b
hw-ai-agent set --max-rounds 30 --max-tokens 4096 --mode safe
hw-ai-agent set --plan --tasks --journal --cost-estimate
hw-ai-agent set --no-plan --no-tasks --no-journal --no-route
hw-ai-agent set --env-file .env.local --provider ollama --max-rounds 40
hw-ai-agent help set
hw-ai-agent help run
```

| Переменная `.env` | Флаг / назначение |
| --- | --- |
| `AGENT_PROVIDER` | `--provider`: `openrouter`, `openai`, `ollama` |
| `OPENROUTER_MODEL`, `OPENAI_MODEL`, `OLLAMA_MODEL` | `--model`: ID для выбранного провайдера |
| `OPENROUTER_API_KEY`, `OPENAI_API_KEY` | Ключи; `set` не принимает ключи |
| `OPENROUTER_BASE_URL`, `OPENAI_BASE_URL`, `OLLAMA_BASE_URL` | Адрес сервиса в настройках, отдельного CLI-флага нет |
| `AGENT_WORKSPACE` | `--workspace`: папка для `run`/`plan` |
| `AGENT_MODE` | `--mode safe/auto` |
| `AGENT_APPROVALS` | `--approvals ask/deny` |
| `AGENT_POLICY` | `--policy`: необязательный JSON вне workspace |
| `AGENT_STATE_DB` | `--state-db`: SQLite вне workspace |
| `AGENT_MAX_ROUNDS` | `--max-rounds` |
| `AGENT_MAX_TOKENS` | `--max-tokens` |
| `AGENT_MAX_TOOL_CALLS` | `--max-tool-calls` |
| `AGENT_MAX_SIDE_EFFECTS` | `--max-side-effects` |
| `AGENT_MAX_RESULT_BYTES` | `--max-result-bytes` |
| `AGENT_PLAN` | `--plan` / `--no-plan` |
| `AGENT_TASKS` | `--tasks` / `--no-tasks` |
| `AGENT_JOURNAL` | `--journal` / `--no-journal` |
| `AGENT_COST_ESTIMATE` | `--cost-estimate` / `--no-cost-estimate` |
| `AGENT_ROUTE` | `--route` / `--no-route` |
| `AGENT_ROUTE_SIMPLE_MODEL` | `--route-simple-model` |
| `AGENT_ROUTE_MEDIUM_MODEL` | `--route-medium-model` |
| `AGENT_ROUTE_COMPLEX_MODEL` | `--route-complex-model` |

Булевы значения в `.env` — `true`/`false`. `setup` записывает общие значения
12 запросов и 2048 выходных токенов; они действуют и для демо. Только при отсутствии
этих переменных используются отдельные встроенные значения: `workflow-demo`,
`plan-demo`, `rollback-demo` — 20/2048, `tasks-demo` — 30/3072.

`plan` всегда планирует, `tasks-demo` всегда использует задачи, `rollback-demo`
всегда включает журнал. Флаги `--offline`, `--crash-after-write`,
`--stop-after-tools N` и `--stop-after-tasks N` задаются только на запуск;
смотрите доступность через `help КОМАНДА`. Для демо `--workspace` должен указывать
новую папку; без него создаётся `workspace/<название>-<время>`, `AGENT_WORKSPACE`
для демо не используется.

## Демонстрации

| Команда | Сценарий | Источник ответов |
| --- | --- | --- |
| `demo` | Исправление скидки, шесть защищённых тестов, независимая проверка | Настоящая модель |
| `policy-demo` | Разрешения, отказы, защита тестов/секретов и путей | Без модели |
| `session-demo` | Пауза после записи и продолжение без её повтора | Подставная модель |
| `workflow-demo` | Исправление нескольких модулей и удаление лишних | Настоящая модель; `--offline` — меньший сценарий восстановления |
| `plan-demo` | Утверждение плана и исправление скидки | Настоящая модель; есть `--offline` |
| `budget-demo` | Исчерпание бюджетов, резервирование, сохранение после сбоя | Подставные ответы |
| `tasks-demo` | Налог, чек и тесты как задачи с зависимостями | Настоящая модель; есть `--offline` |
| `rollback-demo` | План, исправление, просмотр изменений и ручной откат | Настоящая модель; есть `--offline` |
| `cost-demo` | Оценка/расход, продолжение, неизвестная цена и роутинг | Тестовые тарифы и ответы, без сети |

Все демо без API:

```bash
hw-ai-agent policy-demo
hw-ai-agent session-demo
hw-ai-agent budget-demo
hw-ai-agent cost-demo
hw-ai-agent workflow-demo --offline --mode auto
hw-ai-agent plan-demo --offline --mode auto
hw-ai-agent tasks-demo --offline --mode auto
hw-ai-agent rollback-demo --offline --mode auto
hw-ai-agent changes
hw-ai-agent rollback
```

План подтвердите в терминале; `auto` не утверждает его автоматически.
`rollback-demo` сначала выводит `DEMO PASS`, но сам не откатывает: используйте
`changes`/`rollback` с его ID или выбором в меню.

Варианты с настоящими моделями:

```bash
hw-ai-agent demo --provider openrouter --model deepseek/deepseek-v3.2 --mode safe
hw-ai-agent workflow-demo --provider openrouter --mode auto --max-rounds 30
hw-ai-agent plan-demo --provider openai --env-file .env.openai --model gpt-4.1-mini --max-rounds 30
hw-ai-agent tasks-demo --provider ollama --env-file .env.ollama --model qwen3:4b --mode auto --max-rounds 30 --max-tokens 4096
hw-ai-agent rollback-demo --provider openrouter --mode auto --max-rounds 30
```

У пяти демо с настоящей моделью можно заменить провайдера и ID через
`--provider`/`--model`; без `--model` используется настройка выбранного провайдера.
Подставной ответ проверяет механизм, но не качество настоящей модели.
Полный `WORKFLOW DEMO PASS` требует прохождения четырёх тестов и удаления
минимум двух лишних модулей; исправление без очистки является частичным успехом.

Результаты сохраняются в workspace демо в JSON с моделью, событиями, diff,
проверками и расходом. Итог определяет проверяющий код, а не фраза модели.
Исторические примеры: [базовое демо](docs/DEMO_RESULTS.md),
[policy](docs/POLICY_RESULTS.md), [сессии](docs/SESSION_RESULTS.md),
[workflow](docs/WORKFLOW_RESULTS.md). Они относятся к сохранённым версиям.

## Команды управления

| Команда | Назначение |
| --- | --- |
| `help [COMMAND]`, `COMMAND --help` | Инструкция и флаги; нет обращений к модели |
| `setup`, `set`, `doctor` | Создание настроек, изменение параметров, проверка подключения |
| `run REQUEST`, `plan REQUEST` | Работа со своей папкой |
| `models` | Тарифы, характеристики и цена одинакового сценария |
| `sessions`, `session ID` | Список сессий и подробности одной |
| `resume [ID]` | Продолжение, утверждение плана и решения конфликтов в терминале |
| `approve-plan ID`, `reject-plan ID` | Сохранение явного решения по плану; затем `resume` при утверждении |
| `resolve ID --call KEY --resolution ...` | Явное решение неопределённого вызова |
| `changes [ID]`, `rollback [ID]` | Просмотр журнала и восстановление |
| `cost [ID]` | Сохранённый расход без запроса к модели |

## Проверка проекта

```bash
REQUIRE_SANDBOX_TESTS=1 python -m unittest discover -s tests -v
```

На macOS этот запуск требует работающей системной песочницы и не допускает
пропуска её проверок. Без переменной часть системных тестов может быть пропущена.
Тесты покрывают цикл агента, HTTP-клиент, policy и файловую защиту, реальные
процессы Bash, аварии, восстановление, планы, бюджеты, задачи, откат, настройки
и стоимость. Для генерации и тарифов используются подставные ответы: платный
API не вызывается, качество модели так не измеряется.

GitHub Actions настроен на `macos-latest`, Python 3.11/3.13/3.14 и обязательные
системные проверки. Результат конкретного запуска CI проверяется отдельно.
Отчёты демо, workspace, `.env` и `.agent` исключены из Git. Произвольный текст
модели и файлов в журнале/отчётах может содержать чувствительные данные;
перед публикацией просмотрите выбранный JSON.

## Устройство проекта

| Модуль | Ответственность |
| --- | --- |
| `agent.py`, `client.py` | Цикл модели/инструментов и HTTP-подключение |
| `tools.py`, `filesystem.py`, `policy.py` | Проверки и исполнение инструментов |
| `session.py`, `terminal.py` | SQLite, продолжение, вопросы в терминале |
| `planning.py`, `tasks.py`, `budget.py` | План, зависимости, доказательства, лимиты |
| `journal.py` | Снимки, diff, конфликты и откат |

| `cli.py`, `config.py`, `usage.py` | Команды, настройки и справка |
| `*_demo.py`, `reporting.py`, `tests/` | Сценарии, отчёты и автоматические проверки |

Проект рассчитан на небольшие локальные задачи. Bash ограничен macOS и
разрешёнными командами; защищённые тесты нельзя создавать или исправлять
инструментом записи. Смена модели/бюджетов начатой сессии, автоматический откат,
жёсткий денежный лимит и гарантия качества роутинга не реализованы.
