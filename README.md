# agi

Консольный coding agent на Python: получает задачу, изучает файлы, предлагает
план, изменяет код и запускает проверку. Цикл работы и управление инструментами
реализованы в проекте без агентного фреймворка. Подключение модели — через
OpenAI-совместимый Chat Completions API.

Поддерживаются OpenRouter, прямой OpenAI и локальная Ollama. Нужны Python 3.11+
и `certifi`. Для Bash требуется macOS с `/usr/bin/sandbox-exec`; на других ОС
исполнение команд отклоняется. Небезопасного запасного режима нет.

## Что реализовано

- Чтение и список файлов, запись, восстановимое удаление и ограниченный Bash.
- Режимы Safe/Auto, JSON-policy, защита тестов, секретов и границ рабочей папки.
- Сохранение сессий в SQLite, пауза, продолжение и явное разрешение неоднозначных вызовов.
- Планирование с утверждением плана в терминале до изменения файлов.
- Общие бюджеты запросов к модели, инструментов, действий и объёма результатов.
- Задачи с зависимостями, чек-листом и проверкой фактического результата.
- Журнал изменений, просмотр diff и откат с обнаружением внешних правок.
- Компактный терминальный вывод, цветной diff и опциональный ход работы.
- Каталог скиллов с загрузкой инструкций по запросу модели и статистикой в чате.
- Подключение локальных MCP-серверов через `stdio`, включая учебный трекер.
- Автоматическая A/B-проверка скиллов с отдельными сессиями и результатами каждой попытки.
- Предварительная оценка стоимости, учёт расхода сессии, сравнение тарифов моделей.
- Выбор модели в терминале и автоматический выбор по сложности задачи при старте.
- Настройки через `.env` и CLI, русская справка и автоматические тесты.

## Установка

```bash
git clone https://github.com/SmegCoder/hw_ai_agent.git
cd hw_ai_agent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
agi help
```

`python3` должен быть версии 3.11 или новее. В PyCharm выберите интерпретатор
`.venv/bin/python`. Все команды ниже запускаются из корня проекта с активированной
`.venv`. Можно также использовать `python -m hw_ai_agent` вместо `agi`.

## Подключение модели

Для нового файла настроек:

```bash
agi setup --provider openrouter --model deepseek/deepseek-v3.2
agi doctor --provider openrouter
agi run --workspace /path/to/my-project "Объясни устройство проекта"
```

`setup` запрашивает ключ скрытым вводом и создаёт `.env` с правами `0600`.
Существующий файл не перезаписывается. Если `.env` уже настроен, пропустите
`setup`; параметры меняйте через `set`, ключи — локально в файле.
`doctor` проверяет песочницу и настройки. Для Ollama он также проверяет доступность сервера и модели.

Для другого провайдера можно создать отдельный профиль:

```bash
agi setup --env-file .env.openai --provider openai --model gpt-4.1-mini
agi run --env-file .env.openai --workspace /path/to/my-project "Объясни устройство проекта"

agi setup --env-file .env.ollama --provider ollama --model qwen3:4b
agi run --env-file .env.ollama --workspace /path/to/my-project "Объясни устройство проекта"
```

Для Ollama заранее запустите локальный сервер и загрузите модель с поддержкой
tools. ID должен совпадать с установленным тегом. OpenRouter/OpenAI требуют
собственного ключа и доступной модели; их генерация может тарифицироваться.
Профиль `.env.ollama` не требует ключа. Пример переменных — [.env.example](.env.example).

## Работа со своей папкой

Рабочая папка должна существовать. Модель получает доступ к ней через инструменты;
ключи, policy и база сессий должны находиться вне этой папки.

```bash
agi run --workspace /path/to/my-project \
  "Исправь расчёт суммы заказа и проверь существующими unittest-тестами"

agi plan --workspace /path/to/my-project --mode safe \
  --tasks --journal --max-rounds 30 --max-tokens 4096 \
  "Исправь расчёт суммы заказа и проверь существующими unittest-тестами"
```

`plan` автоматически добавляет инструкцию составить структурированный план;
писать «сначала составь план» в задаче не нужно. До утверждения разрешены только
список и чтение файлов, Bash и изменения запрещены. В терминале `y` утверждает
план, `n` отклоняет и завершает сессию, Enter оставляет её на паузе.
`run --plan` включает то же поведение. `--tasks` автоматически включает планирование.

План содержит цель, короткие шаги и критерии готовности. Существенные риски
и допущения показаны перед утверждением. При режиме задач шаги дополнительно
получают ID, зависимости и проверку результата. План и решение пользователя
сохраняются в SQLite.

Агент запускает подходящие существующие тесты. Если их нет, он может закончить
правку и сообщить, что тесты не запускались. В режиме задач для такой правки
используется проверка записи файла.

### Выбор рабочей папки

Запустите `agi run "Задача"`, `agi plan "Задача"` или `agi chat` в терминале.
Без `--workspace` агент покажет папки внутри `./workspace`.

- Введите номер, чтобы открыть существующую папку.
- Нажмите Enter, чтобы создать папку с сегодняшней датой, например `2026-11-24`.
  При повторном запуске в тот же день агент добавит суффикс `-2`, `-3` и так далее.
- Введите `n`, чтобы создать папку со своим именем.

Явный `--workspace` пропускает выбор. При запуске из скрипта используется
`AGENT_WORKSPACE` из настроек или `./workspace`. Продолжение сессии открывает
сохранённую рабочую папку.

### Компактный вывод

У каждого запуска `run` или `plan` своя сессия. В начале CLI показывает
команду, рабочую папку и модель. В конце отдельный блок перечисляет файлы,
результат тестов и расход API. Если запустить с `--journal`, в блоке появится
команда просмотра diff. В диалоге для этого есть `/changes`.

В режиме `safe` CLI показывает diff перед подтверждением записи и отдельно
спрашивает разрешение на Bash. В diff добавленные строки зелёные, а удалённые
красные. Та же подсветка работает в `agi changes` и `/changes`. При
`NO_COLOR=1` и перенаправлении вывода остаётся обычный текст со знаками `+` и `-`.

### Ход работы

По умолчанию CLI показывает время от начала запроса и короткое действие агента.
Например, `00:02  Чтение · notes.txt`. Флаг `--progress full` показывает аргументы
и результат каждого вызова инструмента, а также токены каждого обращения к модели.
Режим `brief` объединяет последовательные обращения к файлам по действию.
Например, `00:02  Читаю main.py, config.py` и `00:04  Изменяю main.py`.
В строке видны первые три разных пути и число остальных. Ошибки и запросы
подтверждения выводятся сразу. Полный журнал доступен через `agi events ID`.

```bash
agi chat
agi chat --progress brief
agi chat --progress full
agi resume chat --progress full
```

`agi set --progress full` сохраняет настройку для будущих запусков.
Поддерживаются `brief`, `compact`, `full` и `off`. Прежние значения `AGENT_PROGRESS=true`
и `false` означают `compact` и `off`. Флаг `--no-progress` выключает прогресс
для текущего запуска. `--verbose` добавляет диагностику бюджетов и решений policy.

## Диалог с агентом

```bash
agi chat --workspace /path/to/my-project
agi resume chat
agi chat --resume ID
```

`agi resume chat` предлагает выбрать номер диалога. В списке видны последняя активность,
рабочая папка и последний запрос. Команда `/end` закрывает диалог и убирает его из списка.

Введите запрос после приглашения `Вы ›`. Следующие запросы получают ваши
предыдущие сообщения и итоговые ответы агента. Каждый запрос имеет свой бюджет
и журнал рабочей папки. Снимок создаётся перед выполнением, а правки сохраняются
после изменяющих действий. У журнала действуют те же правила доступа и проверки
внешних правок, что у обычного `rollback`.

| Команда | Действие |
| --- | --- |
| `/plan ТЕКСТ` | Сначала утвердить план для этого запроса |
| `/changes` | Посмотреть последние сохранённые правки |
| `/rollback` | Откатить последний запрос с правками, затем продолжить диалог. Если есть приостановленный запрос, отмена сначала относится к нему. |
| `/tokens` | Показать суммарный расход токенов за все обращения в диалоге |
| `/stats` | Показать обращения к модели, токены API, вызовы инструментов и загрузки скиллов по запросам и за диалог |
| `/settings` | Показать настройки диалога |
| `/set ИМЯ ЗНАЧЕНИЕ` | Изменить настройку и сохранить её в диалоге |
| `/resume` | Довести до конца приостановленный запрос |
| `/exit` или Ctrl+C | Выйти с сохранением диалога и получить команду повторного открытия |
| `/end` | Окончательно закрыть диалог и сохранить историю |
| `/help` | Показать команды |

Например, `/set mode safe` включает проверку записи файлов и запуска Bash,
`/set approvals deny` автоматически отклоняет действия, требующие подтверждения,
а `/set max-tool-calls 20` ограничивает каждый новый запрос двадцатью вызовами
инструментов. Также можно менять `max-rounds`, `max-side-effects` и `max-tokens`.
Настройки сохраняются после `agi chat --resume ID`. Команда `/resume` продолжает
уже начатый запрос с параметрами его контрольной точки.

`/set progress brief`, `/set progress compact`, `/set progress full` и `/set progress off` меняют
вывод сразу и сохраняют выбор для этого диалога. Флаг командной строки при
повторном открытии действует до выхода из чата.

После ответа чат показывает суммарный расход токенов одной строкой. При откате
ранее учтённые токены остаются в счётчике. Знак `≈` означает, что часть данных
пришлось оценить.

В `/stats` поле `unknown` означает, что провайдер не сообщил значение.
Пометка «частично, 2/3» рядом с числом означает сумму известных значений
двух обращений из трёх. Кэшированные входные токены входят в число входных один раз.
Оценки размера текста хранятся в отдельных полях событий.

### Журнал событий

При любом режиме прогресса агент сохраняет события в SQLite по мере работы.
Запрос инструмента, решение policy и результат связаны по `tool_call_id`.
Для обращения к модели `usage_status` принимает значения `complete`, `partial` и `unknown`. Чтобы получить JSONL, передайте
ID диалога из заголовка чата или ID запроса из `/stats`. Команда работает
и после закрытия диалога, без обращения к модели.

```bash
agi events ID > events.jsonl
```

Для нестандартного пути к базе добавьте `--state-db ПУТЬ`.
Каждая строка содержит стабильный `id`, время UTC `time`, тип `type`,
данные `data`, общий для диалога `session_id` и отдельный `run_id` запроса.
При `/resume` события добавляются к прежнему запросу. У одиночного `agi run`
оба идентификатора совпадают. У записей старого формата время равно `null`.

Для проверки начните `agi chat --mode safe --workspace ./workspace`, попросите
«Создай notes.txt с текстом Первая версия» и подтвердите запись. Затем отправьте
«Замени в нём текст на Вторая версия» и отклоните запись. Откройте `/stats`,
выйдите через `/exit` и экспортируйте журнал. В `notes.txt` должна остаться первая
версия. В журнале можно сверить запросы, вызовы `write_file`, решения
`policy_decision` и результаты `tool_result`.

Чат показывает окно контекста модели из каталога OpenRouter при открытии.
Агент перед каждым обращением оценивает
размер истории, схем инструментов и резерв под ответ. При 80% окна появляется
предупреждение. Если оценка выше предела, запрос останавливается до отправки.
Оценка приблизительная. При переполнении можно сократить новый запрос или
открыть новый диалог с большим контекстом. История сохраняется без автоматического
сжатия.

При временном сбое OpenRouter агент повторяет обращение до двух раз, пока
позволяет лимит обращений к модели. Если сервер прислал `Retry-After`, агент
ждёт указанное время до 30 секунд или сообщает, когда можно повторить запрос.
После ошибки чат показывает причину и предлагает `/resume`, если ещё есть
доступные обращения к модели.

## Скиллы

При запуске `agi chat`, `agi run` или `agi plan` модель получает только имена и
описания доступных скиллов. Подходящие инструкции она запрашивает через инструмент
`load_skill` с аргументом `name`. Например, запрос «Выгрузи открытые учебные задачи»
соответствует `open-task-export`, а «Составь отчёт о просроченных задачах на
2026-11-25» соответствует `deadline-report`. Для обычного сохранения заметки скилл
не нужен. Загрузка инструкций оставляет проверки и подтверждения инструментов в силе.

| Скилл | Действие и результат по умолчанию |
| --- | --- |
| `open-task-export` | Выгрузить незавершённые учебные задачи в `open-tasks.json` |
| `deadline-report` | Собрать задачи, просроченные на заданную дату, в `deadlines.json` |
| `review-python-tests` | Проверить существующие Python-тесты и перечислить пробелы в проверках |

Оба учебных скилла принимают `tasks.json` в рабочей папке или указанный пользователем
файл. Формат входа — массив задач или объект с массивом `tasks`. Поля задачи —
`id`, `title`, `status` и необязательное `due_date` в формате `YYYY-MM-DD`.
Незавершённые статусы — `open`, `todo`, `in_progress`, `blocked`. Если нужны только
сведения в чате, попросите вернуть результат без записи файла.

```bash
agi chat --workspace ./workspace --skills-dir ./my-skills
agi chat --workspace ./workspace --no-skills
```

Чтобы добавить скилл, положите UTF-8 файл `SKILL.md` в папку
`my-skills/<имя-скилла>/` вне рабочей папки агента. При следующем запуске агент
подхватит его автоматически. Заголовок содержит две однострочные записи
`name` и `description` между строками `---`, дальше идут инструкции в Markdown.
Имя совпадает с именем папки, описание занимает до 300 символов, а весь файл — до
16 КиБ. Имя использует строчные латинские буквы, цифры и дефисы.

```markdown
---
name: project-summary
description: Summarize project status from the workspace changelog.
---

Read the changelog and summarize completed items and open questions.
```

Агент пропускает повреждённый файл или дубликат имени и продолжает загрузку
каталога. `--no-skills` отключает каталог и `load_skill` для новых сессий.
В `agi events ID` событие `skills_discovered` перечисляет скиллы, доступные
запросу, а `skill_loaded` фиксирует успешную загрузку с именем и `tool_call_id`.
`/stats` показывает число уникальных обнаруженных скиллов и число успешных
загрузок с разбивкой по именам.

## MCP и учебный трекер

```bash
agi chat --workspace ./workspace --mcp-config mcp/tracker.json --policy policies/tracker.json
```

В чате можно запросить «Прочитай задачи учебного трекера и сохрани в
`open-tasks.json` массив ID незавершённых задач», затем уточнить «Какие из этих
задач просрочены на 25 ноября 2026?». Если агент попросит подтвердить запись,
одобрите её в терминале. В снимке `mcp/tasks.json` незавершённые задачи имеют ID
`T1`, `T3` и `T4`. Снимок существует отдельно от рабочей папки. Флаг `--no-skills`
меняет только доступ к скиллам, подключение MCP и политика остаются прежними.

Клиент начинает соединение с `initialize`, получает схемы через `tools/list`
и посылает выбранный моделью `tools/call`. Он поддерживает последовательные
запросы по `stdio`, пагинацию списка инструментов и текстовые или JSON-результаты.
Локальные процессы открываются для обнаружения и отдельно для каждого вызова.
В режиме `plan` инструменты MCP становятся доступны после подтверждения плана.
Для сценариев с MCP используйте `run`, `chat` или `plan` без `--tasks`.
[Спецификация MCP stdio](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

В `mcp/tracker.json` ключ `tracker` задаёт имя сервера. `snapshot` указывает на
JSON-файл относительно конфига, `allow_tools` перечисляет доступные инструменты,
`timeout` ограничивает соединение со всеми его запросами в секундах. Свой сервер
получает один открытый на чтение дескриптор снимка. Его единственный инструмент
`list_tasks` принимает пустой объект и возвращает `tasks`.

Другой совместимый stdio-сервер подключается через новую запись в `servers`.
Для него задайте `command` массивом из пути к исполняемому файлу и фиксированных
аргументов, `read_paths` со списком дополнительных путей для чтения, `allow_tools`
и `timeout`. Агент запускает такие команды на macOS через `sandbox-exec`, без сети
и с доступом на чтение к системным файлам и явно указанным путям вне рабочей папки.
Готовый сервер должен выдерживать отдельное соединение на каждый вызов.
Конфиг, пути запуска и данные источника хранятся вне рабочей папки агента.

Для каждого разрешённого MCP-инструмента добавьте отдельное правило policy.
Имя `mcp__tracker__list_tasks` обозначает сервер `tracker` и инструмент
`list_tasks`. Действия `allow`, `ask` и `deny` работают с приоритетом запрета.
Сервер не получает аргументы отклонённого вызова. В `agi events ID` видны
обнаружение, сервер, инструмент, аргументы, решения policy, результаты и ошибки.
В `/stats` MCP-вызовы группируются по паре `сервер/инструмент`. Таймаут и ошибки
сервера возвращаются модели как ошибки инструмента, чтобы она могла объяснить
сбой или использовать другой разрешённый источник.

## A/B-проверка скиллов

```bash
agi eval run --provider ollama --model qwen3:4b-instruct --output .agent/evals/hw2
```

Команда запускает пять сценариев по три раза в каждой версии, всего 30 попыток.
В A каталог и загрузчик скиллов выключены, в B включены. Модель, MCP, снимки
данных, запросы, лимиты и правила доступа одинаковы. Подходит модель с вызовами
инструментов. Без `--provider` и `--model` используются значения из `.env`.
Для короткой проверки можно выбрать `--trials 1` и отдельный путь `--output`.

| Сценарий | Проверка результата | Ожидаемый скилл в B |
| --- | --- | --- |
| `open-tasks` | `open-tasks.json` содержит ID незавершённых задач без дублей | `open-task-export` |
| `deadlines` | `deadlines.json` содержит точные сроки, дни просрочки и порядок задач | `deadline-report` |
| `note` | Содержимое `note.txt` побайтно совпадает с указанной фразой | Без скилла |
| `missing-deadlines` | `deadlines.json` отделяет неизвестные сроки от просроченных | `deadline-report` |
| `mcp-failure` | Агент сообщает о сбое трекера и оставляет рабочую папку пустой | `open-task-export` |

У каждой попытки чистая папка, собственный SQLite и отдельный `run_id`.
Трекер читает копию снимка вне рабочей папки. Проверяющий код и эталон агенту
недоступны. Проверки результата, выбора скилла и необходимых вызовов независимы.
В обеих версиях автоматическая запись разрешена только для файла сценария,
а подтверждения, требующие ввода, отклоняются. По умолчанию у попытки 180 секунд
и до восьми обращений к модели. Сетевые ошибки, таймауты и исчерпание бюджета
остаются в результатах.

- `manifest.json` фиксирует гипотезу, модель, настройки, версии кода и хеши снимков.
- `results.jsonl` содержит по строке на попытку, включая проверки и расход токенов.
- `summary.md` и `summary.json` показывают сравнение по сценариям, токены и покрытие usage, вызовы, ошибки и результаты выбора скиллов. Из `summary.md` можно открыть `events.jsonl` каждой попытки.

Для продолжения после Ctrl+C повторите ту же команду. Уже сохранённые попытки
пропускаются по ключу «сценарий, версия, номер». Сохранённая сессия без итоговой
строки обрабатывается из SQLite. Для другой модели, лимитов или версии кода
используйте новый путь `--output`.

## Режимы и policy

| Действие | `safe` | `auto` |
| --- | --- | --- |
| Список и чтение файлов | По policy | По policy |
| Запись | Подтверждение каждого вызова | Сразу после проверок |
| Bash | Подтверждение каждого вызова | Сразу после проверок |
| Удаление | Подтверждение каждого вызова | Подтверждение каждого вызова |

По умолчанию чтение разрешено. Policy может дополнительно запретить его или
потребовать подтверждение. В Safe `allow` не отменяет подтверждение записи/Bash.
В Auto для записи/Bash отдельного разрешения на сессию нет. Явный `deny` действует
в обоих режимах и не может быть отменён ответом пользователя.

Перед подтверждением записи показывается цветной diff, перед удалением — цель и размер.
`--approvals ask` задаёт вопросы; `--approvals deny` отклоняет действия, требующие
этого подтверждения. Это не автоматическое согласие. Утверждение плана и решения
конфликтов задаются отдельно. Если нужен ответ, а stdin не является терминалом,
ожидание сохраняется и запуск останавливается с кодом 130; продолжите через `resume`.

```bash
agi run --workspace /path/to/my-project --mode safe \
  --policy policies/readonly.json "Объясни устройство проекта"
```

Готовые профили:

| Файл | Назначение |
| --- | --- |
| [readonly.json](policies/readonly.json) | Только список и чтение; изменения и Bash запрещены |
| [review.json](policies/review.json) | Просмотр и правки с ограниченным набором команд; каталог `private` закрыт |

JSON-policy задаёт `defaults`, `rules` и `directories.allow/deny`. Приоритет решений
— `deny`, затем `ask`, затем `allow`. Загруженный файл является полной конфигурацией:
неуказанные инструменты запрещены, без `directories.allow` доступных каталогов нет.
Подробнее — [Policy и подтверждения](docs/POLICY_RESULTS.md).

### Границы инструментов

Все вызовы проходят проверку аргументов, путей, policy и режима. Запрещены выход
за workspace, работа через симлинки и жёсткие ссылки, изменение тестов и доступ
к защищённым секретам. Файловые операции повторно проверяют цель после
подтверждения; подмена файла или каталога приводит к отказу.

Bash допускает ограниченные команды: `python -m unittest`, `pwd`, `ls`, `cat`,
`sleep`. Pipes, перенаправления, произвольные скрипты, `python -c`, `pytest`
и `npm` не поддерживаются. Дочернему процессу запрещены сеть и запись в workspace,
а вывод и время исполнения ограничены. Тесты с записью временных файлов могут
не работать в такой песочнице.

`delete_file` удаляет только обычный файл и сохраняет восстановимую копию в
`trash/RECOVERY_ID/file` рядом с базой сессий. `info.json` содержит исходный путь.
Это не автоматический откат; каталоги не удаляются, перенос между файловыми
системами отклоняется. Подробнее — [Руководство по workflow](docs/WORKFLOW_GUIDE.md).

## Сессии, пауза и продолжение

```bash
agi plan --workspace /path/to/my-project --stop-after-tools 2 "Исправь ошибку"
agi sessions
agi resume
agi session SESSION_ID
agi resume SESSION_ID
```

Без ID `resume` в интерактивном терминале выбирает единственную незавершённую
сессию или показывает меню. Для автоматизации без терминала передайте ID.
Флаги паузы не наследуются. Для отдельного профиля и базы при продолжении укажите
те же `--env-file` и `--state-db`.

SQLite хранит историю, вызовы и результаты, план, задачи, бюджеты и стоимость.
Путь по умолчанию — `.agent/sessions.sqlite3`, вне workspace. API-ключ из настроек
не записывается в метаданные; рабочая история не зашифрована.
Повтор завершённого ID вызова возвращает сохранённый результат; изменение его
имени или аргументов является ошибкой протокола.

Модель, провайдер, адрес сервиса, режим, policy и лимиты фиксируются в сессии.
`resume` не поддерживает их переопределение; изменённая policy или несовместимое
подключение блокируют продолжение. Изменение `.env` или `set` влияет на новые
запуски. При `resume` можно менять вывод оценки стоимости, способ подтверждений
и флаги паузы. Одновременное продолжение одной сессии блокируется.

### Неопределённый результат после сбоя

Если действие началось, но его результат не сохранён, оно становится `uncertain`.
Даже чтение не повторяется молча. `resume` показывает состояние и меню:

| Выбор | Действие |
| --- | --- |
| `1` / `retry` | Повторить поддержанный инструмент после проверок; новая попытка расходует бюджет |
| `2` / `skip` | Сохранить ошибку вызова и продолжить |
| `3` / `abort` | Завершить сессию с ошибкой |
| `4` / `applied` | Признать запись только при точном совпадении байтов с запрошенным содержимым |
| `0` | Оставить сессию заблокированной |

`skip` и `abort` не отменяют уже случившиеся изменения. При включённом журнале
дополнительно требуется указать принадлежность обнаруженных изменений:
`own` — изменения сессии, `external` — внешние. Подробнее и команды для
автоматизации — [Сохранение сессий](docs/SESSION_RESULTS.md).

## Бюджеты

| Флаг | Что ограничивает | Встроенное значение для `run` |
| --- | --- | ---: |
| `--max-rounds` | Все попытки запросов к модели | 12 |
| `--max-tool-calls` | Вызовы инструментов | 128 |
| `--max-side-effects` | Попытки записи, удаления и Bash | 32 |
| `--max-result-bytes` | Суммарные байты UTF-8 результатов инструментов | 1 000 000 |
| `--max-tokens` | Выходные токены одного ответа модели | 2048 |

Первые четыре бюджета общие для планирования, исполнения и `resume`.
Пачка инструментов резервируется целиком до первого действия: при недостатке
бюджета её начало не выполняется. Большие результаты обрезаются с отметкой.
После аварии неиспользованный резерв неопределённого вызова не возвращается.
Повтор, ручное решение и откат не обнуляют бюджет. При исчерпании сохраняется
`budget_exhausted`; увеличить лимиты через `resume` нельзя.

`--max-rounds` и `--max-tokens` должны быть не меньше 1; три остальных бюджета
могут быть нулевыми. Bash учитывается как потенциальный побочный эффект, хотя
песочница запрещает ему запись. `--max-tokens` не задаёт контекст, общий объём
токенов или денежный лимит.

## Задачи с зависимостями

`--tasks` превращает утверждённый план в задачи с `id`, `depends_on`, инструментами
и `verification`. Валидатор проверяет ссылки и отсутствие циклов. Планировщик
запускает готовые задачи по очереди; каждый исполнительный вызов связан с задачей.
Чек-лист показывает ожидание, исполнение, успех, ошибку и блокировку зависимостей.

Модель вызывает `complete_task`, но результат проверяет runtime:

- `file_written` — текущие байты совпадают с последней успешной записью этой задачи;
- `file_read` — файл соответствует полному чтению этой задачи;
- `file_absent` — удалённый файл отсутствует;
- `tests_passed` — нужная команда unittest прошла, запускала тесты и её вывод не обрезан.

Текст «готово» и доказательства, придуманные моделью, не завершают задачу.
Ошибка блокирует зависимые задачи; независимые могут продолжиться. После `resume`
завершённые задачи не исполняются заново. Состояния и проверенное доказательство
сохраняются в SQLite вместе с завершением задачи.

## Журнал изменений и откат

Журнал включается **при создании** сессии через `--journal`.
Для старого запуска без журнала откат недоступен.

```bash
agi plan --workspace /path/to/my-project --journal "Исправь ошибку"
agi changes
agi rollback
```

`changes [SESSION_ID]` показывает diff, `rollback [SESSION_ID]` возвращает исходные
байты и обычные права доступа изменённых файлов; созданные агентом файлы удаляются.
Откат запускается отдельной командой, доступен и для завершённой сессии.
Каждое удаление при откате подтверждается в обоих режимах.

Перед изменяющим инструментом фактическое дерево сверяется с последней контрольной
точкой. Внешняя правка блокирует действие. Перед откатом проверяются все затронутые
файлы, сохранённые данные и текущая policy. Конфликт или отказ при предварительных
подтверждениях не запускает восстановление. Чужие изменения незатронутых файлов
сохраняются. Проверки повторяются после подтверждений.

Многофайловый откат не является атомарной транзакцией файловой системы:
авария или гонка во время исполнения может оставить часть восстановленной.
Состояние `rollback_pending` сохраняется; повторный `rollback` явно продолжает
оставшиеся операции. После успешного отката сессия получает `rolled_back`
и исполнение агента не возобновляется. История, стоимость и бюджет сохраняются.

Ограничения снимка: 2000 путей, 10 MiB на файл, 20 MiB на дерево.
Защищённые служебные файлы исключаются;
обычные JSON-файлы отслеживаются. Снимок не обходит запрет чтения policy.
Восстанавливаются байты и mode, но не владелец, ACL или xattr; пустые каталоги
могут остаться. Подробнее — [Руководство по workflow](docs/WORKFLOW_GUIDE.md).

## Стоимость и выбор модели

По умолчанию перед каждым запросом показывается приблизительная цена при выходе
от 0 до `--max-tokens`. Оценка учитывает историю и схемы инструментов, использует
приближение числа токенов и не предсказывает стоимость всей будущей задачи.
После ответа и по завершении показывается накопленный расход сессии.

```bash
agi run --workspace /path/to/my-project --no-cost-estimate "Исправь ошибку"
agi resume --cost-estimate
agi cost
agi cost SESSION_ID
agi set --no-cost-estimate
```

`AGENT_COST_ESTIMATE=true/false` задаёт значение по умолчанию.
`--no-cost-estimate` отключает предварительную оценку, но учёт фактического
расхода продолжает работать. Этот флаг доступен также при `resume`.

Для OpenRouter приоритет имеет сообщённый `usage.cost`. Для OpenAI сумма
рассчитывается по фактическим токенам и тарифам Standard, с учётом известных
тарифов кэша и длинного контекста. Это расчёт, а не сверка счёта аккаунта.
Ollama и подставные клиенты имеют нулевую плату API; расходы компьютера не учтены.
Неизвестная цена или запрос без сохранённых данных не считаются бесплатными.
Подтверждённые и расчётные суммы хранятся отдельно, суммирование использует Decimal.
Отклонённый ответ модели тоже может быть платным; `resume` и откат не обнуляют расход.

### Сравнение тарифов

```bash
agi models --provider openrouter --refresh
agi models --provider openrouter --paid --limit 100
agi models --provider openrouter --free --sort price
agi models --provider openrouter --search deepseek --all
agi models --provider openai --search gpt-4.1
agi models --provider ollama
agi models --provider openrouter --input-tokens 10000 --output-tokens 2000 --json
```

Колонки показывают полный ID, тариф входа/выхода за миллион токенов, контекст,
поддержку tools и цену одинакового сценария. По умолчанию — до 50 моделей по
имени, сначала с подтверждёнными tools; `--all` снимает лимит, `--limit` допускает
1–5000. `--paid` и `--free` взаимоисключающие, неизвестные цены исключаются из них.
Это сравнение тарифов, а не рейтинг популярности или качества.

OpenRouter использует публичный каталог, OpenAI — официальную таблицу Standard,
Ollama — установленные модели и их capabilities. Кэш вне workspace действует
час; при сбое старые данные помечаются устаревшими с датой. Без данных цена
неизвестна. Для нестандартного endpoint или неподтверждённого service tier
официальный тариф не подставляется. Каталог не гарантирует доступ модели аккаунту.

### Ручной и автоматический выбор

```bash
agi run --workspace /path/to/my-project --model '?' "Исправь ошибку"
agi plan --workspace /path/to/my-project --model auto "Исправь ошибку"
agi set --route
agi set --no-route
```

`--model '?'` показывает до 20 вариантов с ценами и номерами; кавычки защищают
`?` от обработки оболочкой. Enter/0/EOF отменяют выбор. Для запуска без терминала
нужен явный ID или `auto`. Выбор не меняет `.env`.

`--model auto` или `--route` локально оценивают описание задачи, планирование и
режим задач, затем выбирают одну модель из набора simple/medium/complex.
Платного классификатора нет. Причины выбора печатаются и сохраняются; при
`resume` модель не выбирается заново. Явный `--model ID` имеет приоритет над
`AGENT_ROUTE`. Наборы определены в [routing.py](src/hw_ai_agent/routing.py).

Переопределения: `--route-simple-model`, `--route-medium-model`,
`--route-complex-model`. Модель должна иметь подтверждённые tools, известный
тариф и подходящие известные лимиты. При отсутствии кандидата запуск завершается
ошибкой. Эвристика не гарантирует лучшего качества; жёсткого денежного бюджета нет.

## Настройки и флаги

Приоритет: **CLI → экспортированная переменная → `.env` → встроенное значение**.
`set` сохраняет только указанные настройки, сохраняет остальные строки и ключи,
создаёт файл при необходимости, не вызывает модель. Уже экспортированная
переменная продолжает иметь приоритет над записанным файлом.

```bash
agi set --provider ollama --model qwen3:4b
agi set --max-rounds 30 --max-tokens 4096 --mode safe
agi set --plan --tasks --journal --cost-estimate
agi set --no-plan --no-tasks --no-journal --no-route
agi set --env-file .env.local --provider ollama --max-rounds 40
agi help set
agi help run
```

| Переменная `.env` | Флаг / назначение |
| --- | --- |
| `AGENT_PROVIDER` | `--provider`: `openrouter`, `openai`, `ollama` |
| `OPENROUTER_MODEL`, `OPENAI_MODEL`, `OLLAMA_MODEL` | `--model`: ID для выбранного провайдера |
| `OPENROUTER_API_KEY`, `OPENAI_API_KEY` | Ключи; `set` не принимает ключи |
| `OPENROUTER_BASE_URL`, `OPENAI_BASE_URL`, `OLLAMA_BASE_URL` | Адрес сервиса в настройках, отдельного CLI-флага нет |
| `AGENT_WORKSPACE` | `--workspace`: папка для `run`/`plan` |
| `AGENT_MODE` | `--mode safe/auto` |
| `AGENT_APPROVALS` | `--approvals ask/deny` |
| `AGENT_POLICY` | `--policy`: необязательный JSON вне workspace |
| `AGENT_STATE_DB` | `--state-db`: SQLite вне workspace |
| `AGENT_MAX_ROUNDS` | `--max-rounds` |
| `AGENT_MAX_TOKENS` | `--max-tokens` |
| `AGENT_MAX_TOOL_CALLS` | `--max-tool-calls` |
| `AGENT_MAX_SIDE_EFFECTS` | `--max-side-effects` |
| `AGENT_MAX_RESULT_BYTES` | `--max-result-bytes` |
| `AGENT_PLAN` | `--plan` / `--no-plan` |
| `AGENT_TASKS` | `--tasks` / `--no-tasks` |
| `AGENT_JOURNAL` | `--journal` / `--no-journal` |
| `AGENT_PROGRESS` | `--progress brief\|compact\|full\|off` (по умолчанию `compact`) |
| `AGENT_COST_ESTIMATE` | `--cost-estimate` / `--no-cost-estimate` |
| `AGENT_ROUTE` | `--route` / `--no-route` |
| `AGENT_ROUTE_SIMPLE_MODEL` | `--route-simple-model` |
| `AGENT_ROUTE_MEDIUM_MODEL` | `--route-medium-model` |
| `AGENT_ROUTE_COMPLEX_MODEL` | `--route-complex-model` |

Булевы значения в `.env` — `true`/`false`. `setup` записывает общие значения
12 запросов и 2048 выходных токенов. Эти же значения используются
по умолчанию при отсутствии настроек.

`plan` всегда включает планирование. Флаги `--stop-after-tools N`
и `--stop-after-tasks N` действуют только на текущий запуск.

## Команды управления

| Команда | Назначение |
| --- | --- |
| `help [COMMAND]`, `COMMAND --help` | Инструкция и флаги; нет обращений к модели |
| `setup`, `set`, `doctor` | Создание настроек, изменение параметров, проверка подключения |
| `run REQUEST`, `plan REQUEST` | Отдельный запрос к агенту |
| `chat`, `chat --resume ID` | Новый или сохранённый интерактивный диалог |
| `models` | Тарифы, характеристики и цена одинакового сценария |
| `sessions`, `session ID` | Список сессий и подробности одной |
| `resume [ID]` | Продолжение, утверждение плана и решения конфликтов в терминале |
| `approve-plan ID`, `reject-plan ID` | Сохранение явного решения по плану; затем `resume` при утверждении |
| `resolve ID --call KEY --resolution ...` | Явное решение неопределённого вызова |
| `changes [ID]`, `rollback [ID]` | Просмотр журнала и восстановление |
| `cost [ID]` | Сохранённый расход без запроса к модели |

## Проверка проекта

```bash
REQUIRE_SANDBOX_TESTS=1 python -m unittest discover -s tests -v
```

На macOS этот запуск требует работающей системной песочницы и не допускает
пропуска её проверок. Без переменной часть системных тестов может быть пропущена.
Тесты покрывают цикл агента, HTTP-клиент, policy и файловую защиту, реальные
процессы Bash, аварии, восстановление, планы, бюджеты, задачи, откат, настройки
и стоимость. Для генерации и тарифов используются подставные ответы: платный
API не вызывается, качество модели так не измеряется.

GitHub Actions настроен на `macos-latest`, Python 3.11/3.13/3.14 и обязательные
системные проверки. Результат конкретного запуска CI проверяется отдельно.
`.env` и `.agent` исключены из Git. История сессии может содержать
рабочие файлы и ответы модели.

## Устройство проекта

| Модуль | Ответственность |
| --- | --- |
| `agent.py`, `client.py` | Цикл модели/инструментов и HTTP-подключение |
| `tools.py`, `filesystem.py`, `policy.py` | Проверки и исполнение инструментов |
| `session.py`, `terminal.py` | SQLite, продолжение, вопросы в терминале |
| `planning.py`, `tasks.py`, `budget.py` | План, зависимости, доказательства, лимиты |
| `journal.py` | Снимки, diff, конфликты и откат |
| `pricing.py`, `model_catalog.py`, `routing.py` | Расход, каталоги и выбор модели |
| `cli.py`, `config.py`, `usage.py` | Команды, настройки и справка |
| `tests/` | Автоматические проверки |

Проект рассчитан на небольшие локальные задачи. Bash ограничен macOS и
разрешёнными командами; защищённые тесты нельзя создавать или исправлять
инструментом записи. Смена модели/бюджетов начатой сессии, автоматический откат,
жёсткий денежный лимит и гарантия качества роутинга не реализованы.
