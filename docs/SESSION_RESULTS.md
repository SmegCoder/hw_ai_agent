# Сохранение и продолжение сессий

## Что сохраняется

SQLite `.agent/sessions.sqlite3` хранит задачу, историю, ответы модели,
вызовы и результаты, решения оператора, план, задачи, бюджеты, расход
и журнал изменений при его включении. База вне workspace, имеет права `0600`
и исключена из Git. API-ключ из настроек не записывается в метаданные.
Рабочая история не зашифрована.

Ответ модели и пачка инструментов сохраняются до исполнения. Перед действием
вызов становится `running`; результат и история фиксируются одной транзакцией.
Ожидание ответа пользователя сохраняется как `awaiting_approval`.
Это позволяет продолжить после паузы или перезапуска процесса.

Завершённые вызовы не исполняются заново. Повтор завершённого `tool_call_id`
возвращает сохранённый результат; смена имени или аргументов этого ID является
ошибкой протокола. В режиме задач ID дополнительно связан с текущей задачей.
Одновременное продолжение сессии блокируется.

## Как пользоваться

```bash
hw-ai-agent demo --provider ollama --model qwen3:4b --mode auto --stop-after-tools 1
hw-ai-agent sessions
hw-ai-agent resume
hw-ai-agent session SESSION_ID
hw-ai-agent resume SESSION_ID
```

Пауза после сохранённого результата возвращает код 130. `resume` без ID в терминале
выбирает единственную незавершённую сессию либо предлагает меню.
Без терминала передайте ID. Флаг паузы не наследуется.
Для отдельной базы всем командам нужен прежний `--state-db`; при отдельном
профиле подключения передавайте прежний `--env-file`.

При продолжении используются сохранённые провайдер, модель, адрес сервиса,
режим, policy и лимиты. Смена модели или увеличение бюджета через `resume`
не поддерживаются; `set` и новые настройки влияют на новые сессии.
Изменённая policy или несовместимое подключение блокируют продолжение.
Можно менять `--cost-estimate`/`--no-cost-estimate`, `--approvals` и флаги паузы.
Стоимость и общий бюджет не сбрасываются.

## Утверждение плана

Plan Mode сохраняет предложенный JSON и состояние планирования в той же базе.
До утверждения разрешены только список и чтение. `resume` выводит план и вопрос
прямо в терминале. `y` утверждает, `n` отклоняет и завершает сессию,
Enter оставляет её ожидающей. Решение и сообщение в истории фиксируются вместе.

Для автоматизации:

```bash
hw-ai-agent approve-plan SESSION_ID
hw-ai-agent resume SESSION_ID
# Альтернативное решение:
hw-ai-agent reject-plan SESSION_ID
```

## Неопределённые вызовы

Файловое действие и SQLite не образуют общую транзакцию. Если процесс погиб
после действия, но до сохранения результата, начатый вызов становится `uncertain`.
Продолжение блокируется до решения пользователя, в том числе для чтения и Bash.
`resume` показывает вызов, состояние файла и варианты в терминале:

| Выбор | Значение |
| --- | --- |
| `1` / `retry` | Новая попытка поддержанного инструмента после проверок |
| `2` / `skip` | Сохранить ошибку и продолжить без повтора |
| `3` / `abort` | Окончательно завершить с ошибкой |
| `4` / `applied` | Только запись: принять результат при точном совпадении байтов |
| `0` | Сохранить блокировку |

`skip` и `abort` не откатывают произошедшее действие. `retry` расходует бюджет
и проходит policy/подтверждения заново. `applied` не принимает похожий текст,
другие окончания строк или содержимое с добавленным комментарием.
Сетевой запрос без сохранённого ответа может повториться и повторно тарифицироваться.

При журнале после сбоя нужно также определить принадлежность показанных изменений:
`own` — включить в журнал сессии; `external` — исключить из отката этого вызова.
Если внешняя правка затронула более ранний результат агента, его откат тоже
может быть заблокирован. Изменения после просмотра требуют нового решения.

Для автоматизации ключ вызова берите из `unfinished_calls` команды `session`:

```bash
hw-ai-agent resolve SESSION_ID --call CALL_KEY --resolution applied --changes own
hw-ai-agent resume SESSION_ID
```

`--changes` требуется для соответствующего конфликта журнала; без журнала
его не передавайте. Ключи отличаются между сценариями. Пример реальной аварии —
в [WORKFLOW_GUIDE.md](WORKFLOW_GUIDE.md).

## Проверка

```bash
hw-ai-agent session-demo
REQUIRE_SANDBOX_TESTS=1 python -m unittest discover -s tests -v
```

`SESSION DEMO PASS` подтверждает сохранение записи один раз, открытие базы заново,
исполнение ожидающих тестов и неизменность контрольного файла. Клиент подставной,
инструменты настоящие. Тесты дополнительно проверяют реальные аварии между
эффектом и результатом, решения неопределённых вызовов, сохранение плана,
задач, бюджета и расхода. База использует схему версии 5; миграции сохраняют историю.
