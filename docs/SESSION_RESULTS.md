# Сохранение и восстановление сессии

## Текущее поведение

SQLite-журнал `.agent/sessions.sqlite3` сохраняет задачу, историю, ответы модели,
вызовы, результаты, решения оператора, лимиты и счётчик модельных запросов.
База находится вне workspace, исключена из Git и создаётся с правами `0600`.
API-ключ из настроек не записывается. Журнал содержит рабочую историю и не зашифрован.

Ответ модели и пачка инструментов сохраняются до исполнения. Перед действием
вызов становится `running`, результат и история сохраняются одной транзакцией.
При вопросе подтверждения состояние — `awaiting_approval`: прерывание на вопросе
не означает, что инструмент уже выполнился. `resume` снова запросит ответ.

Любой начатый вызов без сохранённого результата становится `uncertain`, включая
Bash и чтение. Продолжение блокируется до решения оператора. Завершённые вызовы
не повторяются. Повтор завершённого `tool_call_id` возвращает сохранённый результат;
смена имени или аргументов этого ID вызывает ошибку протокола. Явный `retry`
фиксируется как новая попытка того же вызова.

Счётчик запросов не обнуляется. При продолжении проверяются workspace, policy,
модель, адрес сервера, ограничения и режим. В Safe каждый изменяющий вызов и
Bash подтверждаются отдельно; в Auto запись и Bash идут сразу после проверок.
Каждое удаление подтверждается заново в обоих режимах. Разрешения на сессию
из старых версий не используются. Одновременное продолжение блокируется.

## Проверка без API

```bash
hw-ai-agent session-demo
REQUIRE_SANDBOX_TESTS=1 python -m unittest discover -s tests -v
```

`SESSION DEMO PASS` означает: запись сохранена один раз, база открыта заново,
выполнены ожидающие тесты, контрольный файл неизменён. Демо использует подставную
модель и настоящие инструменты. Полный набор: 168 тестов без ошибок и пропусков.
Тесты также проверяют настоящий аварийный выход после эффекта и до сохранения
результата, ошибки записи контрольной точки и решения неопределённого вызова.

## Пауза и продолжение с моделью

```bash
hw-ai-agent demo --provider ollama --model qwen3:4b-instruct --mode auto --policy policies/demo.json --stop-after-tools 1
hw-ai-agent sessions
hw-ai-agent session SESSION_ID
hw-ai-agent resume SESSION_ID
```

Замените `SESSION_ID` напечатанным ID. Пауза возвращает код 130 после сохранённого
результата. `resume` продолжает ту же сессию; флаг остановки не наследуется.
Для отдельного файла настроек передавайте его и при продолжении:
`hw-ai-agent resume SESSION_ID --env-file .env.openai`. Для своей базы передавайте
одинаковый `--state-db` всем командам.

При неопределённом вызове сначала посмотрите `session` и проверьте файлы.
Затем выберите одно решение:

| Решение | Результат |
|---|---|
| `retry` | Новая попытка поддержанного инструмента после проверок режима и policy |
| `skip` | Сохранить ошибку и продолжить без повторного действия |
| `abort` | Окончательно завершить с ошибкой; дальнейшее продолжение запрещено |
| `applied` | Для записи: принять результат только при точном совпадении байтов |

Пример для первого вызова аварийного offline-демо:

```bash
hw-ai-agent resolve SESSION_ID --call 1:0 --resolution retry
hw-ai-agent resume SESSION_ID
```

Подробный аварийный сценарий: [WORKFLOW_GUIDE.md](WORKFLOW_GUIDE.md).
Решения `skip` и `abort` не откатывают фактически выполненное действие.

## Исторический запуск Ollama

[session-ollama-demo-report.json](session-ollama-demo-report.json) содержит
успешное продолжение с настоящей `qwen3:4b-instruct`: сохранённый `list_files`
не повторился, модель исправила код, сама запустила шесть тестов, независимая
проверка прошла, тестовый файл неизменён. Итог — `DEMO PASS`.
Это результат предыдущей версии; текущие правила подтверждения проверены отдельно.

Файловое действие и SQLite не образуют общую транзакцию: неопределённость после
сбоя не скрывается. Сетевой запрос без сохранённого ответа может повториться
и повторно тарифицироваться. Plan Mode, общий бюджет и rollback не реализованы.
