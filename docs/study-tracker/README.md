# Учебный трекер и A/B-эксперимент

Агент выгружает открытые задачи, готовит отчёт о сроках и сохраняет результат в рабочей папке. Терминальный диалог, скиллы и MCP используют общий runtime на Python.

## Проверка после клонирования

Команды выполняются из корня репозитория. Для проверки сохранённой серии достаточно Python 3.11+ с зависимостями проекта. Ключ и запущенная модель нужны только для новых запросов.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python scripts/verify_evals.py
python -m unittest discover -s tests
agi doctor session 16f02079049a4e0aa0f1a037d87ba51c --state-db docs/study-tracker/sessions.sqlite3
```

Первая проверка заново открывает файлы всех попыток, применяет критерии результата и выбора инструментов, сверяет статистику с событиями и пересчитывает обе сводки. Ожидаемые итоги — 14/15 для A и 15/15 для B. Отрицательный результат отдельной попытки сохранён в серии и должен совпасть при перепроверке. Для исполнения Bash и сторонних MCP-процессов нужна macOS с работающим `sandbox-exec`. На такой машине полный прогон можно выполнить с `REQUIRE_SANDBOX_TESTS=1 python -m unittest discover -s tests`.

## Итоги эксперимента

Гипотезу зафиксировали перед серией. Ожидалось, что скиллы повысят долю правильных файлов при отборе задач и работе со сроками и могут увеличить расход входных токенов. В этих трёх сценариях A справилась в 8 из 9 попыток, B — в 9 из 9. Разницу дала одна попытка с дедлайнами.

| Метрика по пяти сценариям | A · без скиллов | B · со скиллами |
| --- | ---: | ---: |
| Успех по критерию результата | 14/15 | 15/15 |
| Допустимые и необходимые инструменты | 13/15 | 12/15 |
| Правильный выбор скиллов, включая работу без скилла | н/п | 15/15 |
| Входные токены API | 65 993 | 83 469 |
| Выходные токены API | 5 577 | 5 564 |
| Обращения с известными входными и выходными токенами | 43/43 | 43/43 |

В паре `deadlines` A3 получила данные трекера (событие 17), затем трижды попыталась вызвать Bash. Policy отказала в событиях 27, 37 и 42. Бюджет действий закончился до записи. В B3 модель загрузила `deadline-report` (13), получила тот же снимок (18) и записала файл через `write_file` (31–33). Проверка подтвердила обе просроченные задачи, сортировку и число дней. [Журнал A3](eval/trials/deadlines/A3/events.jsonl) · [Журнал B3](eval/trials/deadlines/B3/events.jsonl) · [Созданный отчёт](eval/trials/deadlines/B3/workspace/deadlines.json)

Поддержка скиллов дала один дополнительный верный результат при росте входа на 17 476 токенов, около 26,5%. В сценарии заметки обе версии записали верный текст 3/3 раза, но B во всех трёх попытках дополнительно запросила запрещённый Bash. Все шесть попыток при сбое MCP сообщили об ограничении и оставили папку пустой. Вывод применим к этим пяти сценариям и трём повторам на версию. [Сводка по каждому сценарию](eval/summary.md)

## Новый запуск

Для своего модельного доступа настройте OpenRouter по инструкции в корневом README. Снимок трекера, policy и разрешённые инструменты runner подготавливает автоматически.

```bash
agi eval run --provider openrouter --model deepseek/deepseek-v4.1-flash --output .agent/evals/recheck
```

Ту же команду можно повторить после прерывания. Смена модели, конфигурации или версии кода требует нового каталога. Для интерактивной проверки создайте рабочую папку и запустите чат.

```bash
mkdir -p workspace/tracker-demo
agi chat --workspace workspace/tracker-demo --mode safe --approvals ask --mcp-config mcp/tracker.json --policy policies/tracker.json
```

Попросите сохранить ID незавершённых задач в `open-tasks.json` и подтвердите запись. Затем спросите «Какие из них просрочены на 25 ноября 2026 года?». Попросите заменить файл только просроченными задачами и отклоните запись. Сверьте содержимое файла, откройте `/stats` и завершите сеанс через `/exit`.

## Версия и состав материалов

Серия записана на Python 3.14.2 с OpenRouter и `deepseek/deepseek-v4.1-flash`, в режиме `auto`, подтверждения `deny`, лимит 8 обращений к модели, до 2048 выходных токенов на ответ и 180 секунд на попытку. Версия `certifi` в окружении серии — 2026.7.22. Коммит `1b040271d78b4b9801ed60680321ef6583c4fd52` в истории репозитория содержит именно тот runtime, который использовался для A/B. SHA-256 всех его модулей и карточек совпадают с манифестом. Отдельную рабочую копию этой версии можно открыть следующей командой.

```bash
git worktree add --detach ../tracker-ab-reproduction 1b040271d78b4b9801ed60680321ef6583c4fd52
```

В той папке выполните установку, настройте свой доступ и запустите команду eval из раздела выше. В текущей версии появились доктор сессий и обновлённый вывод в терминале. Загрузка через `load_skill` теперь проверяет policy, а модель получает файл скилла вместе с YAML-заголовком. В сохранённой серии модель получала полный текст инструкций после заголовка. При новом запуске на текущей версии это может изменить расход и ответы.

В `eval/inputs` лежит по одному экземпляру фактических входов и конфигурации каждого сценария. Их байты сверены для всех шести попыток. В `eval/trials` сохранены исходные журналы и все созданные файлы. Папка пустого результата отсутствует в Git. База для доктора содержит события, статусы, лимиты и финальные ответы 30 запусков. Из неё исключены приватные пути и внутренняя история сообщений провайдера. База предназначена для анализа сохранённого эксперимента.
