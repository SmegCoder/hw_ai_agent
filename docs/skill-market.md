# Локальный маркет скиллов

Маркет читает один доверенный каталог JSON. Каждая запись задаёт имя и описание
скилла, версию, относительный путь к пакету `SKILL.md` и SHA-256 его содержимого.
Демо-каталог находится в [examples/skill-market](../examples/skill-market).
Агент предлагает модели описания ещё не установленных карточек. Для подходящей
карточки модель вызывает `install_skill`, а затем читает её через `load_skill`.
Для установки встроенная policy спрашивает подтверждение. В своей policy
можно явно задать `allow`, `ask` или `deny` для `install_skill`.

Оператор передаёт путь конфигурации через `--market-config`. Конфигурация,
каталог, пакеты и база маркета хранятся вне рабочей папки. Маркет проверяет
имя карточки, формат `SKILL.md` и хеш, запрещает выход за каталог при чтении
пакета и обрабатывает адреса как пути к файлам. Активная версия переключается
в транзакции вместе с сохранением пакета и записи журнала. Начатый или
возобновлённый запуск продолжает использовать закреплённые за ним версии.
Установкой новых карточек управляет policy инструмента. Автообновление уже
установленных карточек управляется конфигурацией оператора.

| Поле конфигурации | Назначение |
| --- | --- |
| `catalog` | Путь к JSON-каталогу, разрешается относительно конфигурации |
| `check_on_start` | Автоматическая проверка в начале каждого нового запроса. По умолчанию `true`. |
| `auto_update` | Автоматическая обработка обновлений установленных карточек. По умолчанию `false`. |
| `require_eval` | Сохранить обновление как кандидата и проверить его перед активацией. По умолчанию `true`. |

При `check_on_start: false` агент может пользоваться сохранённым каталогом и
установленными карточками. Для ручного обновления сведений есть `agi market check`.
Если автообновление выключено, проверка сообщает об обновлении и сохраняет
активную версию. Ошибка чтения каталога или проверка пакета с ошибкой
также сохраняют рабочую версию.

[Проверка обновлений перед активацией](skill-update.md). Демо ниже использует
`require_eval: false`, чтобы показать прямое обновление без запуска модели.

## Демо без API-ключа

Из корня установленного проекта запустите:

```bash
python scripts/demo_skill_market.py
python -m unittest discover -s tests -p 'test_skill_market.py'
```

Демо использует записанные в коде ответы модели, настоящие конфигурации и
пакеты, обычный цикл агента, инструменты и временные базы SQLite. Пример
результата сохранён в [журнале маркета](skill-market-events.jsonl). Пути
источника в приложенном журнале относительные. В нём видны следующие события.

| Этап | Результат |
| --- | --- |
| Первая версия каталога | Обнаружена и установлена `study-week-overview 1.0.0` |
| Вторая версия и выключенное автообновление | Появилась `next-study-task 1.0.0`, обнаружено обновление недельного плана. Версия `1.0.0` осталась активной. |
| Включённое автообновление | Новый запуск проверил и активировал `study-week-overview 1.1.0` |
| Повторная проверка | Каталог без изменений, повторной установки и дубликатов нет |
| Повреждённый пакет | YAML версии `2.0.0` отклонён, активной осталась `1.1.0` |

## Демо с настроенной моделью

Создайте временный реестр, чтобы переключать каталоги из примера.

```bash
demo_dir=$(mktemp -d)
cp -R examples/skill-market/. "$demo_dir/"
cp "$demo_dir/catalog-v1.json" "$demo_dir/catalog.json"
mkdir "$demo_dir/workspace"
agi chat --market-config "$demo_dir/market.json" \
  --workspace "$demo_dir/workspace" --state-db "$demo_dir/sessions.sqlite3"
```

Попросите «Составь план учёбы на неделю, распределив три часа между БД и
RISC-V». Подтвердите установку предложенного `study-week-overview`.
В другом терминале из той же папки проекта, используя тот же путь вместо
`$demo_dir`, или после выхода из чата переключите каталог.

```bash
cp "$demo_dir/catalog-v2.json" "$demo_dir/catalog.json"
```

Следующий запрос автоматически покажет обновление до `1.1.0` и новинку
`next-study-task`. Новый скилл остаётся предложением до вызова установки
по подходящему запросу. Повторите запрос для проверки неизменного каталога.
Команды просмотра установленных версий и журнала работают офлайн:

```bash
agi market status --market-config "$demo_dir/market.json" \
  --workspace "$demo_dir/workspace" --state-db "$demo_dir/sessions.sqlite3"
agi market events --market-config "$demo_dir/market.json" \
  --workspace "$demo_dir/workspace" --state-db "$demo_dir/sessions.sqlite3"
```

В журнале `market_check` содержит время, результат и число записей.
`market_new` сообщает о новом имени. `market_install` и `market_update`
содержат версию, хеш, результат и возможную ошибку. Для обновления журнал
показывает также старую версию и её хеш.
