# Многофайловое демо: сохранённые результаты

## Как воспроизвести

```bash
hw-ai-agent workflow-demo --provider openrouter --mode auto --max-rounds 30
hw-ai-agent workflow-demo --offline --mode safe
```

Первый запуск использует настоящую модель из настроек. Второй — детерминированный
меньший сценарий без API. Установка, режимы, критерии успеха и аварийное
восстановление описаны в [WORKFLOW_GUIDE.md](WORKFLOW_GUIDE.md).

## Сохранённый сценарий восстановления

[workflow-safe-report.json](workflow-safe-report.json) относится к ранней версии
и подставной модели: исправлены `tax.py` и `receipt.py`, два теста прошли,
контрольный файл неизменён. После сохранённого результата была пауза,
затем продолжение той же сессии. Итог — `WORKFLOW DEMO PASS`.

Записанные в этом JSON разрешения на сессию отражают прежнее поведение.
Сейчас Safe подтверждает каждую запись/Bash, оба режима — каждое удаление.
Текущий offline-сценарий требует четыре подтверждения в Safe и не требует
вопросов записи/Bash в Auto. Сохранённый результат проверяет механизм
восстановления той версии и не оценивает выбор действий настоящей моделью.

## Сохранённый запуск Ollama

[workflow-ollama-partial-report.json](workflow-ollama-partial-report.json)
содержит запуск с `qwen3:4b-instruct`: модель исправила функциональные ошибки,
четыре теста прошли, но лишние модули не были удалены.
Поля: `functional_success=true`, `cleanup_complete=false`, `success=false`.

Это частичный результат. Для полного `WORKFLOW DEMO PASS` в расширенном
сценарии нужны и корректность, и удаление минимум двух неиспользуемых модулей.
Отчёт не следует представлять как полный успех или проверку нынешних правил
подтверждений. JSON сохранён как воспроизводимое свидетельство отдельного запуска.
