# Проверка обновлений скиллов

Когда включено автообновление, маркет проверяет новый `SKILL.md` и сохраняет его
как кандидата. Текущая версия продолжает работать до завершения сравнения.
По умолчанию `require_eval` включён. Настройка `require_eval: false` оставляет
режим немедленного обновления для каталогов, где оператор явно его выбрал.

## Сравнение и решение

`agi market evaluate ИМЯ` обновляет сведения о каталоге, берёт сохранённого
кандидата и запускает существующий eval-runner. Манифест фиксирует модель,
лимиты, сценарии и хеши двух снимков. Вариант A получает активную ревизию,
B получает кандидата. Остальные карточки, инструменты, правила, запросы
и снимки трекера одинаковы.

Запускаются **30 независимых сессий**, по три на вариант в каждом из пяти
сценариев. Флаг `--focus СЦЕНАРИЙ` просит загрузить сравниваемый скилл в обеих
версиях выбранного сценария. Он помогает отделить эффект текста карточки
от ошибки выбора скилла. Обычный `agi eval run` сохраняет исходный режим
сравнения с выключенными и включёнными скиллами.

Обновление применяется автоматически, если выполняются все условия:

- В каждом сценарии кандидат получает как минимум столько же верных результатов, сколько активная версия.
- В каждом варианте есть хотя бы один верный результат и хотя бы одна успешная загрузка проверяемой карточки.
- Все 15 попыток кандидата проходят проверку допустимых и необходимых инструментов.
- API вернул входной и выходной usage для каждого обращения в обоих вариантах.
- Средний входной и выходной расход вместе вырос максимум на 20% на попытку. Порог ограничивает дополнительную нагрузку от новой карточки. Число попыток одинаково, поэтому решение сравнивает точные суммы без округления.

При отклонении текущая версия остаётся активной. `summary.md` связывает
попытки с журналами, в `summary.json` находятся метрики, а `decision.json`
содержит решение и причины. Код выхода 0 означает, что сравнение завершено
и решение записано. `agi market candidates` показывает состояние кандидатов.
При прерывании повторите команду с теми же параметрами и папкой вывода.
Завершённые попытки сохраняются. Если опубликованный пакет, настройки
или активная версия изменились во время прогона, применение блокируется.

Для принятого обновления команда чата
`/market-rollback tracker-json-deadlines` восстанавливает предыдущую
ревизию. Уже начатые сессии используют закреплённые копии. Маркет журналирует
откат и сохраняет обе версии и исходный отчёт. Та же откаченная пара версий
при повторной проверке каталога автоматически не применяется.

## Воспроизведение

Выполните команды из корня проекта с установленным `agi` и настроенной моделью.

```bash
demo_dir=$(mktemp -d)
cp -R examples/skill-update/. "$demo_dir/"
cp "$demo_dir/catalog-1.0.0.json" "$demo_dir/catalog.json"
mkdir "$demo_dir/workspace"
agi run --market-config "$demo_dir/market.json" \
  --workspace "$demo_dir/workspace" --state-db "$demo_dir/sessions.sqlite3" \
  'Установи tracker-json-deadlines и загрузи его инструкции.'
```

После установки опубликуйте версию `1.1.0` в тестовом каталоге и запустите
сравнение. Провайдера и модель можно указать явно через `--provider` и `--model`.

```bash
cp "$demo_dir/catalog-1.1.0.json" "$demo_dir/catalog.json"
agi market evaluate tracker-json-deadlines --market-config "$demo_dir/market.json" \
  --workspace "$demo_dir/workspace" --state-db "$demo_dir/sessions.sqlite3" \
  --focus deadlines --focus missing-deadlines --output "$demo_dir/results"
```

Кандидатов и журналы можно просмотреть без подключения к модели.

```bash
agi market candidates --market-config "$demo_dir/market.json" \
  --workspace "$demo_dir/workspace" --state-db "$demo_dir/sessions.sqlite3"
agi market events --market-config "$demo_dir/market.json" \
  --workspace "$demo_dir/workspace" --state-db "$demo_dir/sessions.sqlite3"
```

При принятом обновлении откройте чат с той же конфигурацией и базой, затем
введите `/market-rollback tracker-json-deadlines`. Сценарии принятия, отклонения,
отката, прерывания и смены кандидата проверяются тестами.

```bash
python -m unittest discover -s tests -p 'test_skill_updates.py'
python -m unittest discover -s tests -p 'test_eval_runner.py'
```
