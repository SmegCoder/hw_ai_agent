# Доктор сессий

Доктор работает с сохранёнными событиями SQLite. Он принимает ID всего
диалога или отдельного запуска. Для выгрузки событий с теми же ID используется
команда `agi events ID` с тем же `--state-db`.

## Правила

| Находка | Условие |
| --- | --- |
| Повторяющаяся ошибка | В одном запуске инструмент вернул одинаковый результат ошибки минимум дважды. Для Bash также проверяется ненулевой код выхода. Отдельно считается число известных наборов аргументов. |
| Повторное чтение | В одном запуске `read_file`, `list_files` или `tracker/list_tasks` успешно вернул один и тот же результат с одинаковыми аргументами минимум дважды. Между наблюдениями учитываются операции записи, Bash, восстановление и продолжение сессии. Аргументы JSON сравниваются независимо от порядка полей. |

Для сравнения нужны связанные вызовы и результаты. Обрезанные ответы
пропускаются. Повтор с тем же результатом может быть осознанной проверкой.
Доктор отмечает совпадение и предлагает условно переиспользовать результат,
если повторная проверка не нужна для задачи.

## Реальный запуск с находкой

Попытка `deadlines/A3` от 25 ноября 2026 года использовала
`openrouter/deepseek/deepseek-v4.1-flash`.

```bash
agi doctor session 16f02079049a4e0aa0f1a037d87ba51c \
  --state-db docs/study-tracker/sessions.sqlite3
```

Запуск завершился со статусом `budget_exhausted`. За четыре обращения API
сообщил 7 011 входных и 1 032 выходных токена, всего 8 043. В счётчик входа
уже входят 5 760 токенов чтения кэша. Трекер вызван один раз. Расход самого
доктора составил 0 обращений и 0 токенов.

Доктор нашёл три вызова Bash с разными аргументами и одинаковой ошибкой
`POLICY_DENIED`.

| Вызов | Результат |
| --- | --- |
| `16f02079049a4e0aa0f1a037d87ba51c:25` | `16f02079049a4e0aa0f1a037d87ba51c:27` |
| `16f02079049a4e0aa0f1a037d87ba51c:35` | `16f02079049a4e0aa0f1a037d87ba51c:37` |
| `16f02079049a4e0aa0f1a037d87ba51c:40` | `16f02079049a4e0aa0f1a037d87ba51c:42` |

В этом сценарии можно убрать попытки Bash после отказа. Данные уже доступны
из `tracker/list_tasks`, а политика разрешает записать `deadlines.json`
через `write_file`.

## Реальный запуск без совпадений

```bash
agi doctor session 48502ae0f02848b88bd4e6245929af22 \
  --state-db docs/study-tracker/sessions.sqlite3
```

В `open-tasks/B1` агент один раз загрузил `open-task-export`, один раз
прочитал трекер через MCP и один раз записал файл. Доктор не нашёл совпадений
по двум правилам. В автоматических тестах отдельно проверен первый сценарий
с повторным чтением и похожий случай, в котором два одинаковых чтения
разделяет запись в файл. После записи повторное чтение не помечается.
