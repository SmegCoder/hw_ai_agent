# Policy и подтверждения действий

## Правила исполнения

Каждый вызов проходит `ToolRuntime.execute`: валидацию аргументов, проверку
пути/команды, policy и режима. `deny` имеет приоритет над `ask` и `allow`.
Подтверждение не отменяет явный запрет или ограничения runtime.

| Действие | Safe | Auto |
| --- | --- | --- |
| Список и чтение | По policy; по умолчанию разрешены | По policy; по умолчанию разрешены |
| Запись | Подтверждение каждого вызова | Сразу после проверок |
| Bash | Подтверждение каждого вызова | Сразу после проверок |
| Удаление | Подтверждение каждого вызова | Подтверждение каждого вызова |

В Safe policy-`allow` не отменяет вопрос записи/Bash. В Auto для этих действий
нет первого подтверждения или разрешения на сессию. Policy-`deny` действует
всегда, а чтение с `ask` требует ответа в любом режиме.

Перед записью показывается diff; перед удалением — файл и размер.
Состояние ожидания сохраняется до вопроса. Отказ возвращается модели как
ошибка инструмента. Без терминала запрос остаётся ожидающим, код выхода — 130;
`resume` в терминале снова предлагает ответить.
`--approvals deny` отказывает в требуемых подтверждениях, а не отвечает «да».

## Настройка policy

JSON хранится вне workspace и передаётся через `--policy` или `AGENT_POLICY`.
`defaults` задаёт решение при отсутствии правила, `rules` сопоставляет инструмент
и путь либо полную команду, `directories` ограничивает каталоги и потомков.
Файл является полной конфигурацией: неуказанный инструмент запрещён,
без `directories.allow` доступных каталогов нет.

- [readonly.json](../policies/readonly.json): просмотр без записи, удаления и Bash.
- [review.json](../policies/review.json): правки и ограниченные команды; `private` закрыт.
- [demo.json](../policies/demo.json): запись только `order.py` и конкретный запуск unittest.

```bash
hw-ai-agent demo --provider openrouter --mode auto --policy policies/demo.json --approvals deny
```

Профиль разрешает необходимые запись и тесты в Auto без вопроса, удаление запрещает.
Для демонстрации ручного отказа запустите `demo --mode safe` и ответьте `n` перед
записью: файл не изменится, модель получит ошибку. Итог демо может оказаться неуспешным.

## Защита файлов и процессов

Запрещены выход за workspace, симлинки, жёсткие ссылки, изменение защищённых
тестов и доступ к секретам. Проверенные дескрипторы и повторная проверка
идентичности/содержимого цели защищают от подмены во время подтверждения.

Bash запускается в системной песочнице macOS: сеть и запись в workspace запрещены.
Разрешён ограниченный набор команд; аргументы, cwd, время и вывод проверяются.
Ограничения чтения policy применяются и к процессу. Для Bash поддерживаются
точные пути и шаблоны `*`/`?`; неподдерживаемый шаблон с `[]` приводит к отказу.
При недоступной песочнице команда не запускается. Тесты, которые создают файлы,
могут не работать из-за запрета записи.

## Демонстрация и тесты

```bash
hw-ai-agent policy-demo
REQUIRE_SANDBOX_TESTS=1 python -m unittest discover -s tests -v
```

`policy-demo` не использует модель: ответы оператора заданы сценарием,
файловые инструменты настоящие. Итог — `POLICY DEMO PASS`.
Автоматические проверки дополнительно покрывают режимы, приоритет запретов,
защищённые цели, пути и подмену файлов/каталогов, восстановимое удаление
и системную песочницу.

## Сохранённый пример с моделью

[policy-deepseek-demo-report.json](policy-deepseek-demo-report.json) фиксирует
`DEMO PASS` с `deepseek/deepseek-v3.2`: шесть тестов прошли, файл тестов неизменён,
решения policy сохранены. Это запуск предыдущей версии; он показывает применение
профиля в том запуске, но не подтверждает последующие изменения файловой защиты.

Общие команды — в [README](../README.md), восстановление и удаление —
в [WORKFLOW_GUIDE.md](WORKFLOW_GUIDE.md).
