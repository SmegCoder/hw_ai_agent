# Результаты проверки первого блока

Проведён реальный запуск `deepseek/deepseek-v3.2`
через OpenRouter с пользовательским API-ключом.

Результат: **DEMO PASS**.

- До исправления контрольные тесты падали.
- Модель вызвала `list_files`, прочитала `order.py` и `test_order.py`.
- Два вызова `read_file` были возвращены в одном ответе модели.
- Модель изменила только `order.py`.
- Модель выполнила `python -m unittest discover -v` через `Bash`: 6 тестов прошли.
- Runtime независимо повторил запуск: 6 тестов прошли.
- SHA-256 `test_order.py` до и после совпадает.
- Задача завершилась финальным ответом модели за 5 обращений.
- Стоимость этого успешного прогона по полям `usage.cost`: $0.0011692656.
  Эта сумма не включает предыдущие диагностические прогоны.

Исправленная формула:

```python
subtotal = sum(prices)
return subtotal - subtotal * discount_percent / 100
```

Например, заказ `[100, 50]` со скидкой `10%` теперь стоит `135`,
вместо ошибочных `140`. Добавлена проверка допустимого диапазона скидки.

## Сохранённое доказательство и повторный запуск

Полный отчёт для репозитория: [deepseek-demo-report.json](deepseek-demo-report.json).
В нём сохранены модель, события, результаты тестов до и после исправления,
изменения `order.py`, ответ модели и данные `usage`. Отчёт можно прочитать
после клонирования без API-ключа.

Локальные отчёты сохраняются в `workspace/demo-*/demo-report.json`. Папки `workspace/demo-*`
игнорируются Git и не входят в репозиторий: каждый новый запуск создаёт свою
папку с первоначально сломанным кодом.

В сохранённых JSON-отчётах путь рабочей папки заменён на `workspace/demo`,
включая пути внутри вывода тестов и событий. Домашние каталоги заменяются
на `<home>`, персональные временные каталоги macOS — на `<temp>`.
Это очистка путей, а не удаление секретов из произвольного содержимого файлов:
перед публикацией всё равно просмотрите отчёт.

Для воспроизведения сначала выполните установку из [README](../README.md):
создайте `.venv` на Python 3.11+, активируйте её и установите проект через
`python -m pip install -e .`. Демонстрация требует macOS с `sandbox-exec`.
Затем из корня проекта:

```bash
hw-ai-agent setup --provider openrouter --model deepseek/deepseek-v3.2
hw-ai-agent doctor
hw-ai-agent demo --provider openrouter --model deepseek/deepseek-v3.2
```

Команда `setup` нужна только если локального `.env` ещё нет; ключ вводится
без отображения. Повторная демонстрация использует настоящий платный API.
Ожидаемый итог: `tests_unchanged=true`, `model_ran_passing_tests=true`
в отчёте и `DEMO PASS` в терминале. Наличие ключа проверкой `doctor` не
подтверждает его действительность или достаточный баланс.

Первый реальный запуск нашёл две проблемы: отсутствие доверенных сертификатов
в Python и лишние проверки модели после успешных тестов. Исправлены TLS-настройка
через `certifi` и инструкция завершения. Промежуточные неуспешные прогоны не
засчитываются как успешная демонстрация.

## Автоматические проверки

На момент завершения первого блока полный локальный прогон содержал 27 тестов
и прошёл без пропусков. После добавления policy и исправления её обходов
полный набор после третьего блока вырос до 91 теста;
результаты второго блока описаны в [POLICY_RESULTS.md](POLICY_RESULTS.md).
Проверены цикл агента, обработка ошибок, форматы запросов, ограничения путей,
защита тестов, тайм-аут и объём вывода. Системные проверки подтвердили запрет
чтения внешнего файла и `.env`, записи в тесты, доступа к сети и передачи
API-ключа через окружение дочернего процесса.

Повторная проверка не обращается к платному API:

```bash
REQUIRE_SANDBOX_TESTS=1 python -m unittest discover -s tests -v
```

Без `REQUIRE_SANDBOX_TESTS=1` тринадцать системных проверок пропускаются.
GitHub Actions настроен в `.github/workflows/tests.yml`; его запуск на GitHub
не подтверждается этим локальным отчётом.

## Статус остальных подключений

Подключение OpenAI напрямую реализовано и проверено подставными HTTP-ответами;
реальный OpenAI API не вызывался, ключ для него не предоставлялся.

Ollama установлена и отвечает на запросы, но успешная полная демонстрация
для локальной модели пока не подтверждена. Использованный `qwen3:4b` оказался
Thinking-версией с обязательными размышлениями; наблюдались длинная генерация,
тайм-аут и повторные вызовы инструментов. Контекст в исследованном запуске
составлял 4096 токенов. Повышение `--max-tokens` увеличивает допустимую длину
ответа и не расширяет этот контекст.

Для следующей проверки в README указан `qwen3:4b-instruct`; это вариант
для проверки, а не уже подтверждённый результат. Подтверждённая демонстрация
первого блока в этом отчёте выполнена через DeepSeek/OpenRouter.
